# Implementation Plan: Root Domain Localization & Browser Language Detection

**Branch**: `004-root-localization` | **Date**: 2026-08-03 | **Spec**: [spec.md](file:///d:/Projects/astrology-for-the-future/specs/004-root-localization/spec.md)

**Input**: Feature specification from `/specs/004-root-localization/spec.md`

## Summary

Improve the site's localization architecture so that visiting the root domain (`/`) does not issue a client or HTTP redirect to `/en` or `/es`. Instead, the root domain (`/`) serves static HTML content directly while dynamically adapting to the user's preferred browser language (`navigator.language`) or stored `localStorage` language preference without changing the browser URL. Direct localized URLs (`/en`, `/es`, `/en/*`, `/es/*`) remain fully accessible and functional.

## Technical Context

**Language/Version**: TypeScript / Astro 5 (Static Site Generation)
**Primary Dependencies**: Astro, Tailwind CSS v4, Zod
**Storage**: Client `localStorage` for persisting user language preference across visits
**Testing**: `npm run build` (SSG HTML validation), manual browser language emulation
**Target Platform**: Web (Static HTML / Cloudflare Pages)
**Project Type**: Web Application (SSG)
**Performance Goals**: Instant initial load at `/` with 0 layout shift (CLS < 0.1) and 0 URL redirects
**Constraints**: Must adhere to project Constitution (Strict TypeScript, i18n parity, no automatic git commits, Git Bash commands)
**Scale/Scope**: `src/pages/index.astro`, `src/pages/[...slug].astro`, `src/i18n/index.ts`, `src/components/Global/Navigation.astro`, `src/components/Global/Header.astro`.
